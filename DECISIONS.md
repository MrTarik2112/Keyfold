# Decisions

Where the plan left room, or where this implementation deliberately differs, the
choice and the reason are recorded here.

## 1. VK is wrapped by an HKDF subkey of K1, not by K1 itself

The plan says "VK is stored encrypted by K1". The code derives a key-encryption
key with `HKDF-SHA256(ikm = K1, salt = hkdf_salt, info =
"keyfold/v1/master/vk-wrap")` and wraps VK with that. This keeps K1 from being
used directly as an AEAD key and gives every purpose its own key. CK uses
`HKDF(K1 || K2, info = "keyfold/v1/critical-wrap")`, matching the plan. Recovery
wraps use their own labels. Wrapped-key AAD is `vault_id || label`, so wrapped
material cannot be moved between vaults or purposes.

## 2. The file holds two encrypted payloads, not one

The plan describes "an encrypted payload". The file contains a Standard payload
and a separate Critical payload. This is required for the product behavior: the
Standard tier must load while Critical stays sealed. Critical folder names and
labels therefore remain encrypted until the second password is entered. The
header is JSON length-prefixed between the magic/version and the two blobs; the
format is documented in [SECURITY.md](SECURITY.md).

## 3. Recovery key format

The plan allows either 8 groups of 4 words or 52 base32 characters. The app uses
52 Crockford base32 characters in 13 groups of four (no I, L, O or U). Input
accepts lowercase, spaces, missing dashes and the usual 1/I/L and 0/O confusion.
A 256-bit random key is wrapped for both VK and CK.

## 4. `get_workspace` complements `list_tree`

The plan asks for `list_tree(tier)`. The UI needs the whole workspace (both
tiers' metadata, settings, session flags) after every mutation, so
`get_workspace` returns that in one round trip. `list_tree(tier)` is still
implemented and returns only one tier. Neither returns secret values; only
`get_secret` does, one entry at a time.

## 5. Critical unlock requires a Standard session

`unlock_critical` refuses to run when the vault is locked. This follows from the
key hierarchy: CK is wrapped by K1 and K2 together. Locking the whole vault
therefore also wipes Critical. Locking only Critical leaves Standard open.

## 6. A re-tune rewraps both keys

Argon2 re-tuning changes salt1, salt2 and the KDF parameters, so it must
re-derive K1 and K2 and rewrap VK and CK. It requires both passwords, unlocks
the Critical tier first, and is disabled while the session was opened with the
recovery key (there are no passwords in memory to re-derive from). The vault is
re-saved atomically afterwards.

## 7. Sleep detection

A background thread ticks once per second. If the wall clock jumped more than
five seconds between ticks, the machine slept; the vault locks immediately. The
same ticker enforces both idle timers and emits events so the UI updates without
polling the backend for lock changes.

## 8. Frontend preview harness

`src/lib/preview-backend.ts` implements the command surface in memory so the UI
can be reviewed in a browser (`npm run dev`) without compiling Rust. The IPC
wrapper uses it only when `import.meta.env.DEV` is true **and** the Tauri runtime
is absent. Vite removes the dynamic import from a production build, and outside
that branch the wrapper throws. It never ships in the installer.

## 9. Non-secret UI preferences use localStorage

View mode and sidebar collapse state are the only things persisted in the
webview. They are interface preferences, not vault data or credentials. Secrets,
passwords and derived keys never enter localStorage, sessionStorage or the
Zustand store (the store only holds the masked hint returned by the backend).

## 10. Windows test manifest

Test executables do not inherit Tauri's application manifest, so Windows can
load the legacy comctl32 5.82, which is missing imports used by the linked Tauri
runtime. The process then dies before `main` with `STATUS_ENTRYPOINT_NOT_FOUND`.
`build.rs` embeds a Common-Controls v6 manifest into test binaries only
(`cargo:rustc-link-arg-tests`). The app binary keeps the manifest generated by
`tauri-build`.

## 11. Icons and fonts

The logo is a single SVG (`src-tauri/icons/app-icon.svg`) rendered into the
Windows `.ico` and PNG sizes with `tauri icon`. Inter and JetBrains Mono are
bundled through `@fontsource`, so no font is fetched at runtime.

## 12. Search stays in the backend

Search runs in Rust over the already-decrypted metadata, so it can exclude the
Critical tier unless it is unlocked. The webview never holds a complete index of
Critical labels. Search matches labels, providers and folder names, not secret
values.

## 13. No plaintext export

The plan makes plaintext export optional and says not to build it now. Only the
encrypted vault file can be exported. Import validates the file and requires an
explicit confirmation before replacing the current vault; the previous vault is
kept as `keyfold.vault.bak`.

## 14. Copy clears the clipboard conditionally

After a Copy, a background thread waits the configured clipboard delay (20 s by
default) and clears the clipboard only if it still contains exactly the copied
value. If the user has copied something else in the meantime, that content is
left alone. The backend also stores only a SHA-256 fingerprint of that value, so
locking the vault or the Critical tier can clear an owned clipboard without
retaining the secret.

## 15. DESIGN.md replaced the original indigo accent system

[DESIGN.md](DESIGN.md) describes a Linear-style midnight instrument: void
`#08090a`, carbon `#0f1011`, graphite hairlines, paper-white type and one
functional acid-lime accent `#e4f222`. The app now uses that token set, 6 px
controls, 12 px cards, 4 px badges and Inter with `cv01`, `ss03` and `zero`
enabled. The old indigo/emerald/amber/rose/cyan accent picker was removed: a
vault should not let a cosmetic preference blur which color means an action and
which color means Critical. Folder colors remain a small supporting palette for
organisation only.

## 16. Security hardening beyond the original plan

Four protections were added deliberately:

- **Screen-capture protection** is on by default. The window asks Windows/macOS
  to exclude itself from capture through Tauri's content-protection API, with a
  Settings switch for users who must share their screen.
- **Revealed values are wiped from the webview** whenever the window loses focus,
  becomes hidden, or either tier locks, in addition to the 10-second timer.
- **Clipboard ownership** is tracked by fingerprint, so a manual, idle,
  minimize, sleep or Critical lock can clear only content Keyfold copied.
- **The production build suppresses the browser context menu**, removing an
  affordance that exposes browser controls in a vault window.

The Critical idle timer is also corrected: general pointer/keyboard activity now
only extends the Standard session. The 60-second Critical window is extended by
actual Critical operations (reveal, copy, create, edit, move, delete), never by
work in the Standard tier.
